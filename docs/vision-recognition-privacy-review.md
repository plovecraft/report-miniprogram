# 实验图片外部识别链路审查与最小修复

审查日期：2026-10-11。基线：main `ca46a7f0197a83bd9b9bae4ff575bee8834dad47`。结论仅针对仓库代码和离线测试；没有读取线上环境变量、流量、日志、微信管理平台或模型供应商配置，不能据此断言线上已启用或已经发生泄露。

## 1. 基线的数据流与触发点

| 内容 | 外发情况与条件 |
| --- | --- |
| 普通上传的实验图片 | 保存到 `TaskRecord.image_files`；能被本地图像解码器读取的图片随后可进入外部识别。 |
| ZIP 中 JPG/JPEG/PNG | `material_package.py` 解包到同一图片列表，走相同链路；文件夹名称可能拼入文件名。 |
| 图片中的文字、人脸、背景等 | 原始图片完整字节转换为 Base64 data URL；没有裁剪、脱敏或重编码，因此原文件内的 EXIF 等元数据也随之发送。Base64 是编码，不提供保密性。 |
| 文件名、实验类型 | 基线视觉提示词包含文件名和归一化实验类型。学号、姓名或 ZIP 路径片段若出现在文件名中，也会外发。 |
| `image_ref`、`image_index` | 用于本地结果关联，不写进视觉请求。 |
| 报告 DOCX、指导书 DOC/DOCX/PDF | 此视觉模块不直接发送文档文件或抽取其中的内嵌图片；但其他文本 AI 链路会发送抽取的报告/指导书文字。 |

路径：`main.upload_task_file` → `start_preview_if_ready` → 后台线程 `generate_task_preview` → `docx_builder.build_report_preview` → `build_image_plan` → `image_recognizer.recognize_image_file` → `vision_image_recognizer` → 配置的 `/chat/completions`。

报告和指导书到齐、图片达到 `imageCount` 后，最后一次上传可自动启动预览，无需等待用户确认报告生成。ZIP 上传同样可以触发。修改图片计划会重建预览，可能再次识别；直接服务调用及旧报告写入分组路径也可能调用识别器。基线生成后的 `expected_inserted_image_count` 还会重建图片计划，额外发送相同图片。基线手动分类和 `skip` 仅影响后续排版，不能保证图片未被识别。

请求含模型名称、系统/用户提示词、图片 data URL，以及可选温度/流式参数；HTTP Authorization 携带 API Key。Docker 默认接收接口为 `node-hk.sssaicodeapi.com/api/v1`，模型 `gpt-5.4-mini`；接收域名只能说明直接请求目的地，不能证明最终供应商、实际模型、数据留存或训练政策。

## 2. 开关、失败日志与原测试

- 基线 `VISION_RECOGNITION_ENABLED=0/false/off` 或空值可以阻止视觉请求；缺 Key/模型以及 `LLM_DISABLE_FOR_TESTS=1` 同样会阻止。Key 和模型只检查非空，不能证明凭据有效或模型支持图片。
- Docker 默认开关为 1，但没有内置 Key；这不等于线上必然启用。环境变量在调用时读取；修改运行进程外的部署配置通常需要重新部署/重启。已经发出的请求无法通过关开关撤回。
- 视觉失败日志包含原文件名和 `str(exc)`。HTTP 错误可能包含 URL；自定义异常可能带服务响应、图像或密钥。上层图像失败日志带路径及 traceback，预览错误字段还会回传异常文本。
- 关联报告链路记录原始模型回复、流式坏片段、指导书预览；模型 HTTP 错误还拼接响应正文，AI 排版失败返回原异常。这些都是不必要的敏感内容复制点，不代表已经发现真实泄露。
- 原视觉测试使用程序生成的白色 PNG、虚构 Key 和假 HTTP 返回；没有发现真实用户图片或真实 Key。原测试没有覆盖关开关、未授权、日志脱敏、重定向和 ZIP 端到端路径。
- 原测试环境清空配置并设置测试禁用标志，但未从传输层禁止真实 HTTP；个别测试取消禁用标志后必须依赖正确注入假传输。原报告测试甚至要求原始模型文本出现在日志中。

## 3. 原用户告知与授权机制

没有在业务页面、后端任务字段或识别链路中找到外部图片识别专用告知和授权。微信登录/文件选择授权不等同于向外部模型传输的授权。“自动识别”和报告预览确认也没有说明接收方、传输范围与发生时间。

仓库无法覆盖微信后台另行配置的隐私规则或站外协议，因此不对整个产品是否合规作法律结论。

## 4. 本次最小修复

1. Docker 视觉开关默认改为 0，保留原模型和文本生成配置。
2. 新增 `/api/privacy/vision`，返回实际可用状态、接收域名和告知版本，既不返回 Key，也不返回含凭据的 URL。健康摘要区分开关请求状态和实际可用状态。
3. 创建页添加默认不选、仅本次任务有效的显式同意开关。告知完整图片、ZIP 图片、潜在个人信息/元数据、预览及重建时传输、失败回退与不可撤回；明确图片开关不控制报告文本 AI。获取告知失败则不启用外部图片识别选项。
4. 任务 metadata 记录 `visionRecognitionConsent={accepted,version,recipient}`；后端严格要求 `accepted is True`、版本和当前接收域名一致。未填、字符串 true、过期版本或域名变化一律走本地。旧客户端继续能够生成报告。
5. 底层文件/字节识别接口新增默认 false 的 `allow_external`，任务构建器仅对明确授权的自动分类图片传 true。其他调用路径没有显式授权时默认本地。手动分类、`skip` 与已确认的手动覆盖均不外发。
6. 外发视觉提示词去掉文件名；本地结果仍保留文件名以维持排版关联。仅允许 HTTPS 且拒绝 URL 用户凭据；禁止跟随重定向，3xx 按失败回退。
7. 视觉/图像失败日志只记录异常类型，上层图像错误不回传原异常。删除报告原始模型回复、坏流片段和指导书预览日志；文本 API 与 AI 排版错误不复制供应商正文/原异常。上传和预览开始日志用文件存在状态及图片数量替代文件名。
8. 生成后的质量检查复用已有图片计划；缺计划时仅用本地识别，避免为计数再次发送图片。
9. 测试传输层禁止真实 `requests` 请求；所有新增测试使用合成图片与假服务，不上传用户数据。

功能取舍：未授权任务的自动分类质量可能低于外部视觉模型，但保留现有本地规则、人工分类/预览修改和 DOCX 生成功能。外部服务失败继续回退本地；原来的纯本地不可读图片拒绝逻辑不变。生成后的图片计数现在更贴近用户已确认的计划。

## 6. 部署与剩余事项

需发布后端和小程序后才生效；本次不改线上环境、不合并 main、不触发发布。先保持 `VISION_RECOGNITION_ENABLED=0`。若启用，确认服务支持图片、HTTPS 接收地址正确，并使用无个人信息的合成图片验证；只有已明确同意的新任务会发图片。运行中关闭开关阻止后续调用，但不取消在途请求。

还需由运营方核实并补充模型服务运营主体、服务条款、留存/训练与删除政策及微信隐私规则；不能根据域名的 `hk` 字样判断数据所在地。本次没有自动清除已发出的图片，没有去除原图元数据或建立独立持久化授权审计。现有 TaskStore 在内存中保存任务 metadata 和创建时间，其授权记录不是独立可靠的长期审计存储。

报告文本生成和 AI 排版仍可能将学生/任务 metadata、报告/指导书文字、图片名称与识别出的描述、表格及布局信息发送到外部服务，即使图片识别关闭。本次只降低这些链路的日志风险，不改变它们的业务调用与授权策略，后续应分别完善告知、授权和最小化，不能对用户承诺“关闭图片识别后所有资料都不外发”。同域名供应商策略变化也不能仅靠接收域名校验发现，需要更新告知版本。

检查与配置均不能证明线上历史没有泄露。仍有文件输出路径/质量诊断等既有业务日志及用户可见文件名；本次不宣称对整个仓库所有日志、第三方代理和供应商留存完成脱敏审计。
